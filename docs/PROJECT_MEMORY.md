# MuscleOS 项目记忆

这份文档记录做过的决定和约定，供以后继续开发（人或 AI 助手）时参考。

## 1. 数据规则（不能破坏）

- 缺失 = nil，界面显示「—」；**0 kg 是有效记录**；**组数缺失不能补成 0**。
- 记录类型：力量 `strength`（type 为空也视为力量）、有氧 `cardio`、网球 `tennis`、签到 `check`。
- 状态：空或 `done` 才是实绩；`plan` 计划、`baseline` 历史基线、`cancelled` 已取消、`unconfirmed` 未确认都不计入统计。
- 日期 `yyyy-MM-dd`，空字符串 = 日期待核对，不进任何一周。
- 数据文件 `workouts.json` = `{version, sessions, revisions, profile}`；新增字段一律可选，旧文件必须能读。
- 每次写入前自动备份到 `Backups/`（1 分钟内只留一份，最多 50 份）；编辑留历史版本；删除留「（已删除）」快照供恢复。
- 导出格式兼容网页版（`entries` + `revisions`），用稳定 ID 去重：同 ID 同内容跳过，同 ID 不同内容算冲突、保留本机。

## 2. 统计口径

- 一周从周一开始。
- **直接组数**：每组只算给动作的主练肌群（沿用网页版规则）。
- **含协同**：主练 1 + 协同系数（0.5 主要协同 / 0.25 轻度参与），表在 `Muscles.synergy`，按动作固定，不做"现场公式"。
- 负荷分 = Σ 组数 × (10 − RIR)，RIR 缺失按 3。
- 估算 1RM = 重量 × (1 + 次数 ÷ 30)，次数取第一个数；0 kg 不估算。只在同一动作内比较。
- 逐组记录存在 `setLog`，同时汇总出重量（最重一组）/ 组数 / 次数（相同写一个数，不同按组列）/ RIR（最后一组）。

## 3. 肌群（27 个）

肩：前束、中束、后束｜胸：上部、中下部、前锯肌｜斜方：上、中/菱形、下｜上背：背阔肌、大圆肌｜下背：竖脊肌｜手臂：二头、肱肌/肱桡肌、三头、前臂屈肌群（手心侧）、前臂伸肌群（手背侧）｜核心：腹直肌、深层核心（图上看不到）｜臀：臀大肌、臀中小肌｜大腿：股四头（前）、腘绳（后）、髋内收（内）、阔筋膜张肌/髂胫束（外）｜小腿：腓肠肌、比目鱼肌。

旧名归位：中下斜方/菱形 → 中斜方/菱形；前臂屈伸肌 → 前臂屈肌群；腹斜肌 → 深层核心；髋屈肌 → 腹直肌；肩袖、胫骨前肌 → 未标注。
刻意不做：颈部、肩袖、腹斜肌、胫骨前肌、髋屈肌、盆底肌、阔筋膜以外的冷门肌群。

## 4. 恢复判断

- 按时间：<24 小时「刚练过」，未到建议间隔「恢复中」，之后「可练」。间隔：股四头/腘绳/臀大/竖脊肌 72 小时，其余 48 小时。主练或协同 ≥0.5 都算"练到了"。
- **当天签到**修正：某部位「明显」酸 → 该部位肌群至少「恢复中」；「轻」只注明；疼痛不改颜色，人体图加虚线、面板加提醒。只看当天签到。
- 今日页：睡眠 < 6 小时或疲劳「很累」→ 标题「今天优先恢复」并列出依据。
- 签到全部点选：睡眠半小时一档、疲劳 低/中/高（显示为 精力好/一般/很累）、疼痛部位+程度、酸痛 8 个部位（轻/明显）、蛋白粉开关；改一项自动保存。

## 5. 界面约定

- 左侧边栏：今日、训练、进步、周报、恢复｜规划：计划｜数据：数据与备份｜左下角头像进入「我的」。
- 主色橙红 `#D85A30`，只用于选中、主按钮、强调；疼痛用 `#BA7517`；数字用圆体等宽；卡片圆角 14。
- 尽量点选、不打字；带出的上次数值显示浅色，确认后才保存。
- 只允许一个主窗口。

## 6. 构建与验证

- 只用 Command Line Tools + `swiftc`；SDK 27 缺 SwiftUI 宏插件，`build.sh` 自动用 26.x SDK；默认通用版（arm64 + x86_64）。
- 本机签名，没有公证；分发需要 Developer ID 才能免去首次打开的拦截。
- 验证方式：用 `MUSCLEOS_DATA_DIR` 指向临时目录写测试程序跑逻辑；用 `ImageRenderer` 把界面渲染成 PNG 检查版面。

## 7. 讨论过、决定不做或暂缓

- 账号密码登录、绑定邮箱：需要服务器，破坏离线，单人使用没有意义 → 不做。可选替代：触控 ID 本地锁、备份到 iCloud 云盘文件夹。
- 「我的」页只保留基本信息和伤病与注意；训练目标、每周目标组数、器械偏好、规则设置都不放（目标组数目前只有肩中束 12，写在代码里）。
- 今日推荐（规划模块）占位卡片已删除，等规划模块完成再加。
